# QA: Panda Jump caches its app shell so the installed PWA opens offline

Use desktop Chrome with dev tools' Application and Network panels.

1. Run `npm run build`, then serve `dist/` from a subfolder the way step 17 of `qa/phaser-4-core-run.md` does, e.g. `mkdir -p /tmp/host/PandaJump && cp -r dist/. /tmp/host/PandaJump && npx serve /tmp/host`, and open `/PandaJump/`. **Expected:** the game loads and plays as normal.
2. Open dev tools' Application panel and select "Service Workers". **Expected:** a service worker for the page's origin shows status "activated and is running".
3. Look at the Application panel's "Cache Storage" section. **Expected:** one cache named `panda-jump-<hash>` lists every file the build produced: `index.html`, `manifest.json`, the icons, `assets/index-*.js`, `assets/index-*.css`, and every PNG the game draws (`Panda.png`, the ground and box textures, the two cloud images).
4. In the Network panel, tick "Offline", then reload the page. **Expected:** the page loads exactly as before: the panda runs, box columns still arrive, clouds drift, and every request in the Network panel shows its Size column as "(ServiceWorker)" instead of a byte count or a red failed entry.
5. Play a run to game over while still offline (jump over at least one column, then let a later one hit the panda). **Expected:** the score increments when a column is cleared, and the game-over screen appears exactly as it does online; no request in the Network panel goes to the actual network.
6. Untick "Offline" in the Network panel. Change some build output, e.g. edit `css/style.css`, then run `npm run build` again and re-copy `dist/` over the served folder. Reload the page (still online). **Expected:** dev tools' Application panel shows a new service worker installing and activating, the page reloads itself a second time automatically once the new service worker takes control, the old `panda-jump-<hash>` cache entry is gone from Cache Storage, and a new `panda-jump-<hash>` cache (different hash) holds the rebuilt files, so the change is visible after that automatic reload and no player is stuck on the old build.
7. Run `npm run dev` and open the URL it prints. **Expected:** dev tools' Application panel shows no service worker registered for this origin/port, since `sw.js` only exists in `dist/` and the registration code only runs in a production build.
8. Run `npx playwright test`. **Expected:** every scenario in `features/offline-app-shell.feature` passes.
